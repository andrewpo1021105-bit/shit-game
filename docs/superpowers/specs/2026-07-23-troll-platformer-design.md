# 搞人遊戲 — 設計文件

日期：2026-07-23

## 一句話

一個看起來人畜無害的像素風平台遊戲：走到門口就過關。但關卡會主動整你——地板無聲消失、門自己跑掉、假的通關畫面。玩家會死幾十次，但每次重生只要 0.3 秒。

## 目標與成功標準

- **雙重目標**：能一鍵傳給朋友整他們，同時是能公開發布（itch.io）的完整作品。
- 手機與電腦都能玩。
- 第一版 10〜15 關（本文件規劃 12 關）。
- 成功標準：朋友點開連結後，會在死亡計數破 20 之前笑出來，並且把死亡數截圖傳回群組。

## 核心設計原則

1. **騙局要公平**：所有陷阱在觸發後，玩家都能立刻理解「剛剛發生什麼事」。沒有隨機、沒有看不見的判定。同一個陷阱在同一關永遠在同一個位置以同樣方式觸發。
2. **難的是預測，不是操作**：跳躍手感必須乾淨俐落。死掉永遠是因為被騙，不是因為手滑。
3. **快到來不及生氣**：死亡到重生 0.3 秒內完成。
4. **陷阱是資料，不是程式**：新增一關 = 新增一份資料檔。
5. **節奏是「建立規則 → 打破規則」**：先讓玩家成功一次，再拿那個成功當誘餌。

## 技術方案

- 手寫 Canvas 2D，零遊戲引擎、零建置工具。
- 純 ES modules，靜態檔案，`python -m http.server` 開發，整包 zip 發布。
- 像素圖以「調色盤 + 字串陣列」定義在程式中，啟動時烘焙到 offscreen canvas。無外部圖檔。
- 音效以 WebAudio 即時合成。無外部音檔。

### 檔案結構

```
index.html            畫布與外殼
src/main.js           啟動、主迴圈、場景切換
src/engine/loop.js    固定時間步（accumulator）
src/engine/input.js   鍵盤 + 觸控 → 統一成 {left,right,jump}
src/engine/render.js  像素完美縮放
src/engine/sprites.js 像素陣列 → offscreen canvas 烘焙
src/engine/audio.js   WebAudio 合成音效
src/game/physics.js   AABB 對磁磚碰撞（純函式，可測試）
src/game/player.js    移動與跳躍手感
src/game/world.js     磁磚地圖、實體、狀態
src/game/traps.js     觸發器 / 動作 執行器（純邏輯，可測試）
src/game/levels/      每關一個資料檔
src/ui/               標題、關卡選擇、HUD、結算
test/                 node --test 跑純邏輯單元測試
```

### 顯示

- 16px 磁磚，邏輯解析度 480×270（30×17 格），整數倍放大填滿視窗，`imageSmoothingEnabled = false`。
- 單螢幕一關，不捲動。玩家看得到整關，才會覺得自己是被騙而不是被埋伏。
- 直向手機顯示「請橫置」提示。

### 手感規格（數值為初版，playtest 後微調）

| 項目 | 值 |
|---|---|
| 物理步 | 固定 1/120 秒，渲染插值 |
| 最高水平速度 | 每秒 7 格 |
| 加速 / 煞車 | 0.08 秒到全速，0.06 秒煞停 |
| 跳躍高度 | 約 3.2 格（可變高度：放開鍵切斷上升） |
| 下墜重力 | 上升重力的 1.8 倍 |
| 土狼時間 | 0.10 秒 |
| 跳躍緩衝 | 0.12 秒 |
| 玩家碰撞箱 | 10×14 px |

碰撞為 AABB 對磁磚格，分 X / Y 兩軸依序解算。

### 死亡循環

死亡 → 畫面震動 6 幀 + 玩家像素爆散成粒子 → 0.3 秒內重生於出生點 → 該關陷阱狀態重置（除非該關設計為「記憶型」，見 L12）。

死亡次數全程累計顯示於右上角，永不歸零。這是整人遊戲的靈魂，也是傳給朋友時要比較的數字。

## 陷阱系統

關卡資料由三部分組成：

```js
{
  id, name,
  tiles: [...],           // 30×17 字元地圖
  spawn: [x, y],
  door: [x, y],
  traps: [
    { when: <觸發條件>, do: [<動作>, ...], once: true }
  ]
}
```

### 觸發條件（trigger）

| 名稱 | 說明 |
|---|---|
| `crossX(n)` / `crossY(n)` | 玩家越過某條線 |
| `enterRect(x,y,w,h)` | 玩家進入某區域 |
| `standOn(x,y)` | 玩家踩上某格 |
| `touchDoor` | 玩家碰到門 |
| `afterDelay(t)` | 進關後 t 秒 |
| `deathCount(n)` | 本關已死 n 次（用於「越死越壞」的關卡） |
| `jumpCount(n)` | 玩家已跳 n 次 |

### 動作（action）

| 名稱 | 說明 |
|---|---|
| `removeTiles(rect)` | 地板消失 |
| `addTiles(rect, type)` | 生出方塊／牆 |
| `spawnSpikes(rect, dir)` | 生刺（含天花板落刺） |
| `moveDoor(x, y, speed)` | 門移動／逃跑 |
| `moveTiles(rect, dx, dy, speed)` | 平台移動（含載人） |
| `flipGravity()` | 反轉重力 |
| `invertControls(t)` | 控制反轉 |
| `blackout(t)` | 燈滅，只留輪廓 |
| `crush(rect, speed)` | 天花板下壓 |
| `screenFx(kind)` | 假 UI／假通關／假當機／震動 |
| `sound(id)` | 播放音效（**預設不播**，無聲是陷阱的一部分） |

## 12 關規劃

每關一個新梗，並回收前面的梗當誘餌。

| # | 關卡梗 | 騙局結構 |
|---|---|---|
| 1 | 地板塌陷 | 一條直路。走到門前地板無聲消失。**重生後不再觸發**，讓你順利過關，建立「我學會了」的錯覺。 |
| 2 | 落點也塌 | 明顯的洞，你跳過去——落點的地板在你空中時消失。教你：學到的規則不可靠。 |
| 3 | 門會跑 | 靠近門，門往右滑走。追到底，門滑到牆角無處可逃……然後往上飛，要疊跳才追得到。 |
| 4 | 假門 | 一扇顯眼的門是假的（碰到會關上並落刺）。真門藏在需要故意掉進「陷阱洞」才到得了的地方。 |
| 5 | 地板變刺 | 一整排地板與正常地板同色，踩下去才翻面變刺。安全格有極細微的視覺差異——公平但很賤。 |
| 6 | 牆壁伸出 | 兩側牆壁在你經過時伸出方塊，把你推向坑洞。要靠貼牆跳與煞車閃過。 |
| 7 | 平台丟包 | 移動平台載你到一半，突然加速離開，把你留在空中。 |
| 8 | 天花板下壓 | 天花板緩慢下壓，必須在被壓扁前通過。中途地板還會塌一次。 |
| 9 | 重力反轉 | 走到中段重力反轉，天花板變地板。門也在天花板上——但門是舊的那扇假門。 |
| 10 | 燈滅 | 進關 1.5 秒後全黑，只剩玩家輪廓與門的微光。地圖要用記憶走完，而地圖中途會改變。 |
| 11 | 控制反轉 | 左右顛倒，且本關把 L1〜L10 的陷阱各放一個，全部同時運作。 |
| 12 | 假通關 | 碰到門後跳出完整的「恭喜通關」結算畫面（含死亡數與時間），停留 3 秒後畫面碎裂，真正的最終關開始：門一路逃到畫面外，最後必須主動踩進陷阱、利用塌陷的地板才能抵達真正的出口。**此關為記憶型**：死亡次數會讓陷阱逐步變兇（`deathCount` 觸發器）。 |

## 週邊系統

- **標題畫面**：遊戲標題、開始、關卡選擇、設定。
- **關卡選擇**：格狀選單，每關顯示死亡數與最佳時間。只解鎖已通過的關卡 + 下一關。
- **存檔**：`localStorage`，存進度、各關死亡數、各關最佳時間、總遊玩時間、設定。
- **設定**：音量、螢幕震動開關、色弱友善配色（陷阱與安全地板的差異改用形狀而非顏色）。
- **結算／分享**：全破後顯示「你死了 N 次，花了 M 分 S 秒」，附一鍵複製連結與成績文字的按鈕。
- **暫停**：Esc／手機暫停鈕，含「重來本關」與「回選單」。

### 控制

- 鍵盤：`←/→` 或 `A/D` 移動、`空白/↑/W` 跳、`R` 重來、`Esc` 暫停。
- 觸控：左下虛擬左右鍵，右下跳躍鍵，半透明、可依慣用手左右對調（設定裡）。
- 兩者同時可用，不需切換模式。

## 測試策略

- **單元測試**（`node --test`，零 npm 依賴，`package.json` 僅設 `"type": "module"`）：
  - `physics.js`：AABB 解算的邊界情況——角落擠壓、單幀高速穿透、站在正在移動的平台上、地板在腳下消失的那一幀。
  - `traps.js`：每種觸發器的判定、`once` 語意、關卡重置後的狀態、`deathCount` 累積。
  - 關卡資料驗證：每關的出生點與門都不在牆裡；所有 trap 座標在地圖範圍內；每關在「所有陷阱都不觸發」的假設下必須是可通關的（確保陷阱是唯一的難度來源）。
- **手動 playtest**：每關由開發者盲測 5 次，記錄死亡數。若某關平均死亡數超過 8 次，代表它從「被騙」變成「操作難」，需重新設計。

## 非目標（YAGNI）

- 不做關卡編輯器（12 關手寫資料足夠）。
- 不做多人、排行榜、後端。分享靠複製文字。
- 不做劇情、對話、Boss。
- 不做隨機生成關卡。
- 不做成就系統。
