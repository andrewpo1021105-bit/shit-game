# 搞人遊戲 — 設計文件

日期：2026-07-23（2026-07-23 大改：核心機制從「陷阱目錄」換成「關卡會學你」）

## 一句話

一個像素風平台遊戲：走到門口就過關。但關卡會**側寫你的操作習慣**，並在你每次重生時把關卡改成專門對付你的樣子——而且它會當面告訴你它學到了什麼。

## 遊戲的論點

> 這不是考反應，是考**你能不能不做你一直在做的事**。

你死不是因為手殘，是因為你每次都用同樣的方式起跳，而它算得出來。破關方法永遠存在：改掉那個習慣。難的是你根本停不下來。

## 目標與成功標準

- **雙重目標**：能一鍵傳給朋友整他們，同時是能公開發布（itch.io）的完整作品。
- 手機與電腦都能玩。
- 第一版 12 關。
- 成功標準：朋友玩完之後，會把第 12 關結束時遊戲對他的「分析報告」截圖傳回群組，並且開始互相比對誰的評語比較難聽。

## 四條鐵則

這四條是「關卡會學你」不變成耍賴的唯一保證，任何關卡設計都不得違反：

1. **適應只在重生的瞬間發生。** 跨命的學習（`adapt`）絕不在玩家人在空中時動手。命內的機關（`traps`）則可以隨時翻臉——那是另一回事。
2. **不解釋。** 遊戲不會告訴你它學到什麼、也不會預告陷阱。取而代之的公平性保證是：**陷阱觸發的那一瞬間必須在畫面上看得見**（地板消失、刺彈出來，都伴隨音效與畫面震動），而且重生只要 0.30 秒。你不會知道為什麼，但一定看得到剛剛發生了什麼。
3. **一關只學一件事。** 玩家死幾次之後必須能自己歸納出是哪個習慣害了他。（第 9、12 關例外，見下表。）
4. **反制永遠有效。** 玩家改掉習慣就過得去。適應是根據「上一次」的行為做預測，任何刻意的改變都能打破預測。
5. **出其不意優先於技術難度。** 這是最容易走偏的一條。技術難度是「你知道要做什麼，但做不到」；出其不意是「你以為你知道，結果不是」。這個遊戲只要後者。

   具體檢查方式：**把所有陷阱關掉之後，這一關應該無聊到像教學關**——一條走得完的平路，最多一個小跳。玩家的死因必須 100% 來自被騙，而不是手滑。因此禁止：密集刺陣、需要精確落點的連續跳、跟時間賽跑的關卡、逼玩家用特定跳躍高度連跳好幾次的走廊。

   陷阱應該在玩家**確定自己安全的那一刻**觸發，而不是在他正在應付另一個難關的時候。

另外沿用兩條原有原則：

5. **騙局要公平。** 沒有隨機。同樣的輸入永遠得到同樣的結果。
6. **快到來不及生氣。** 死亡到重生 0.30 秒。

## 側寫系統

側寫器全程在背景收集資料，關卡透過 `adapt()` 讀取它。所有指標都是硬邦邦、可計算、不含糊的量：

| 指標 | 怎麼量 |
|---|---|
| `lastLandTile` | 上一次落地（或墜落穿過地板線）時所在的格 |
| `jumpLead` | 起跳點到障礙邊緣的像素距離 |
| `jumpHold` | 跳躍鍵按住的秒數 → 偏好高跳或點跳 |
| `approachSpeed` | 碰到障礙前 0.5 秒的平均水平速度 |
| `restartDelay` | 死亡到按下第一個方向鍵的間隔 → 急躁度 |
| `hesitation` | 障礙前是否曾經倒退或停下 |
| `routePreference` | 有上下兩條路時走哪條 |

**YAGNI**：只實作當前關卡真正用到的指標，其餘留到需要的那一關再加。

## 12 關 = 12 個習慣

| # | 它學什麼 | 它怎麼還手 |
|---|---|---|
| 1 | （不出手，只收樣本） | 一條直路，走到門前地板無聲消失。建立「這遊戲會騙你」的前提，同時記下你的速度與步伐。 |
| 2 | `lastLandTile` | 洞每次重生都移到**你上次的落點**。你跳幾次它移幾次，直到你發現要改變落點。 |
| 3 | `jumpHold` | 你老是按滿跳躍鍵 → 天花板降到你的最高點以下。改點跳就過得去。 |
| 4 | `approachSpeed` | 你衝過來 → 地板變冰面煞不住；你慢慢走 → 地板變黏走不完。逼你用不習慣的速度。 |
| 5 | `restartDelay` | 你死了馬上重來 → 出生點直接放在刺上。等三秒再動，刺才收起來。這關的解法是不要急。 |
| 6 | `hesitation` | 反過來整龜縮的人：原地站超過 2 秒，地板從腳下一格一格消失。逼你往前。 |
| 7 | `routePreference` | 上下兩條路。你走過的那條下次封死，被迫走陌生的那條。 |
| 8 | `jumpLead` + `jumpHold` | 兩個一起用。門停在你「習慣跳法」剛好搆不到的高度。 |
| 9 | 全部指標 | 畫面側邊即時顯示你的側寫數值，你能看見它在算你。 |
| 10 | 反向操作 | 它宣布「已停止分析」，然後真的不再適應。純靠操作，但你會因為疑神疑鬼而失誤。 |
| 11 | 死亡次數 | 你死越多次關卡越簡單，但通關畫面會記下這個數字。難度是你的自尊。 |
| 12 | 你這個人 | 用**整場遊戲**的側寫生成，每個人的第 12 關都不一樣。通關後顯示完整分析報告。 |

第 12 關的報告就是傳給朋友的東西——不是死亡數，是**遊戲對你的評語**。每個人的都不同，所以會想互相比對。

## 技術方案

- 手寫 Canvas 2D，零遊戲引擎、零建置工具、零 npm 執行期依賴。
- 純 ES modules，靜態檔案。開發用 `python -m http.server`，發布整包 zip。
- 像素圖以「調色盤 + 字串陣列」定義在程式中，啟動時烘焙到 offscreen canvas。無外部圖檔。
- 音效以 WebAudio 即時合成。無外部音檔。
- 純邏輯模組（物理、玩家、陷阱、側寫、關卡資料）不得 import 瀏覽器 API，全部用 `node --test` 覆蓋。

### 檔案結構

```
index.html              畫布與外殼
src/game/constants.js   手感／尺寸常數
src/game/physics.js     AABB 對磁磚碰撞
src/game/player.js      玩家狀態更新
src/game/traps.js       觸發器 / 動作
src/game/profile.js     側寫收集
src/game/world.js       單一關卡的執行期狀態
src/game/session.js     關卡串接、轉場、跨關side的側寫
src/game/levels/        每關一個資料檔（含 adapt()）
src/engine/loop.js      固定時間步
src/engine/input.js     鍵盤 / 觸控
src/engine/sprites.js   像素圖烘焙
src/engine/render.js    像素完美縮放與繪製
src/engine/audio.js     WebAudio 合成音效
src/main.js             組裝
test/                   node --test
```

### 關卡資料格式

```js
{
  id, name,
  tiles: string[],        // 30×17 基礎地形，永遠不被修改
  spawn: [tx, ty],
  door: [tx, ty],
  traps: [ { when, do, once } ],   // 關卡內即時觸發的機關（第 1 關用）
  adapt(tiles, profile) -> { tiles, traps? }   // 重生時重建地形（第 2 關起用）
}
```

- `traps` 處理「這條命之內」的即時反應：地板突然消失、刺突然彈出來。這些是沒有預告的。
- `adapt()` 處理「跨命之間」的學習。**只在 `createWorld` 與 `resetLevel` 時呼叫**，這就是鐵則 1 的實作保證。它可以連同 `traps` 一起換掉，但不得改寫關卡原始資料。
- 遊戲不對玩家解釋任何事，所以沒有提示文字。

### 顯示

- 16px 磁磚，邏輯解析度 480×270（30×17 格），整數倍放大，`imageSmoothingEnabled = false`。
- 單螢幕一關，不捲動。
- 直向手機顯示「請橫置」提示。

### 手感規格

| 項目 | 值 |
|---|---|
| 物理步 | 固定 1/120 秒 |
| 最高水平速度 | 112 px/s（每秒 7 格） |
| 加速 / 煞車 | 1400 / 1867 px/s² |
| 跳躍初速 | 304 px/s（約 3.2 格高） |
| 上升 / 下墜重力 | 900 / 1620 px/s² |
| 土狼時間 | 0.10 秒 |
| 跳躍緩衝 | 0.12 秒 |
| 玩家碰撞箱 | 10×14 px |
| 重生延遲 | 0.30 秒 |

碰撞箱為半開區間 `[x, x+w)`，右／下邊界用 `ceil(x+w)-1` 換算磁磚索引。

### 關卡轉場

過關到下一關之間播放轉場，主題是「它正在分析你」：

1. **0.0〜0.5 秒**：一條亮線由上往下掃過畫面，掃過的部分變成純黑。
2. **0.5〜1.6 秒**：黑畫面中央打字機顯示 `ANALYSING…`，接著一行側寫結果（例：`起跳提前量 34 px`）。
3. **1.6〜2.1 秒**：亮線由下往上掃回，露出下一關。

轉場不只是好看——它是遊戲反覆提醒玩家「你被看著」的節奏點。

### 週邊系統

- 標題畫面、關卡選擇（顯示每關死亡數與最佳時間）。
- `localStorage` 存進度、各關死亡數、最佳時間、設定、**跨場次的側寫**。
- 設定：音量、螢幕震動、色弱友善配色。
- 結算：第 12 關後顯示完整分析報告，附一鍵複製報告文字的按鈕。
- 控制：鍵盤 `←/→ A/D` 移動、`空白/↑/W` 跳、`R` 重來、`Esc` 暫停；觸控為左下方向鍵 + 右下跳躍，可左右對調。

## 測試策略

- **單元測試**（`node --test "test/*.test.js"`，零 npm 依賴）：
  - `physics.js`：角落擠壓、地板在腳下消失、半開區間邊界。
  - `player.js`：土狼時間、跳躍緩衝、可變跳躍高度、站立不抖動。
  - `traps.js`：各觸發器判定、`once` 語意、重生後重置。
  - `profile.js`：各指標的計算與更新時機。
  - **`adapt()` 的可解性**：每關的 `adapt()` 在**任意側寫輸入**下產生的地形都必須是可通關的——出生點不在牆裡、洞不超過可跳距離、門搆得到。這是鐵則 4 的實作保證，也是這個設計最容易出事的地方，測試必須涵蓋極端側寫值。
- **手動 playtest**：每關盲測 5 次。平均死亡數超過 8 次代表它從「被騙」變成「操作難」，需重新設計。

## 非目標（YAGNI）

- 不做關卡編輯器。
- 不做多人、排行榜、後端。分享靠複製文字。
- 不做劇情、對話、Boss。
- 不做隨機生成關卡——所有「變化」都必須來自側寫，且可重現。
- 不做成就系統。
