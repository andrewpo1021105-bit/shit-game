# 借 Level Devil 的把戲，完成第 8～12 關

日期：2026-07-25

## 這份文件的範圍

參考 [Level Devil](https://poki.com/en/g/level-devil) 補進三個我們還沒有的把戲，然後用它們把第 8～12 關做完。

**不在範圍內**：週邊系統（標題畫面、關卡選擇、`localStorage` 存檔、觸控操作、直向提示）另開一份 spec。

## 為什麼是「借把戲」而不是「改架構」

Level Devil 有近 200 個手工編排的短關，靠的是作者想好的驚喜序列。我們是 12 關，靠的是關卡側寫你、針對你。這是兩種不同的遊戲，硬搬結構會稀釋掉核心論點——*「這不是考反應，是考你能不能不做你一直在做的事。」*

所以只借**詞彙**：新機制做成可重用的 trap action，跟 `spawnSpikes`、`moveDoor` 平起平坐，不各自占掉一關。「12 關 = 12 個習慣」的對稱維持不變。

### 對照表

| Level Devil 的把戲 | 我們的狀態 |
|---|---|
| 踩上去才消失的地板 | 已有 `removeTiles` + `standOn` |
| 接近才動的刺／牆 | 已有 `spawnSpikes` / `dropBlock` / `sweepSpike` |
| 假路、假出口 | 已有 `decoys` |
| 門會跑 | 已有 `moveDoor` |
| 左右操作反轉 | **新增 `flipControls`** |
| 物理改變（跳躍高度／重力） | **新增 `setTune`** |
| 破壞規則本身 | **新增 `swapDoor`**（範圍收斂為假門升級版） |

「破壞規則本身」在 Level Devil 指的是 UI 變地形、假當機那類效果。我們刻意收斂成門的欺騙，不碰 `render.js` 的既有結構——成本差太多，而第 12 關真正的重點是分析報告，不是特效。

## 機制層

### `flipControls` — 左右反轉

```js
{ t: 'flipControls', on: true }   // on 預設 true
```

反轉狀態存在 `world.flipped`。`updateWorld` 在把輸入交給 `updatePlayer` 之前對調 `left` / `right`。`applyBuild` 會清成 `false`，所以這是「命內翻臉」而不是「跨命學習」，鐵則 1 不受影響。

**公平性**（鐵則 2）：觸發瞬間推 `flip` 事件 → 音效 + 畫面震動；而且反轉期間 HUD 的 `LEVEL n` 字樣以鏡像繪製。有在看的人看得到。

**與鐵則 7 的衝突**：反轉確實在跟肌肉記憶作對，逼近「難度加在手指」的紅線。解法是讓 `playable.test.js` 的笨機器人讀得到 `world.flipped` 並自行反向按鍵。這樣測試守住的命題變成「只要察覺到反轉，零精準操作就過得去」——反轉只考注意力，不考手速。

### `setTune` — 物理改變

`player.js` 目前直接 import 常數。改成吃一個 tune 物件：

```js
updatePlayer(p, map, input, dt, tune = DEFAULT_TUNE)
```

`DEFAULT_TUNE` 定義在 `constants.js`，欄位為 `maxSpeed` / `accel` / `friction` / `jumpSpeed` / `gravityUp` / `gravityDown` / `jumpCut`，預設值即現有常數。`world.tune` 由 `applyBuild` 建立。

一個 plumbing 同時餵兩種用法：

```js
{ t: 'setTune', tune: { gravityDown: 3400 } }        // 命內突變
adapt() -> { tiles, tune }                            // 跨命依側寫調整
```

現有 5 個測試檔呼叫 `updatePlayer` 的方式不受影響（預設參數）。

### `swapDoor` — 假門升級版

```js
{ t: 'swapDoor', decoy: 0 }
```

真門與第 `decoy` 扇假門**互換位置**。搭配 `touchDoor` 觸發器時，玩家正碰著的那扇會在過關判定之前變成假門——因為 `updateWorld` 的順序是「跑觸發器 → 檢查假門 → 檢查真門」，交換後當場踩中假門判定，直接死。真門則跑到原本假門的位置。

重生時 `applyBuild` 重建 `decoys` 與 `door`，全部復原。配 `deathCount` 觸發器就是「越死越壞」。

### `adapt()` 第三參數

第 11 關要依「本關死亡數」重建地形，但 `profile.attempts` 是跨關累加的，會被前面關卡污染。因此簽章擴充為：

```js
adapt(tiles, profile, ctx)   // ctx = { deaths }
```

`ctx.deaths` 取自 `world.deaths`。現有關卡忽略第三參數，向後相容。

## 側寫層：兩個新指標

| 指標 | 怎麼量 |
|---|---|
| `jumpLead` | 起跳當下，玩家前緣到前方最近一個「不可站」格（洞或刺）邊緣的水平像素距離。往前掃最多 8 格，掃不到就不取樣。 |
| `hesitation` | 每條命一個布林值：玩家是否曾經倒退（`vx` 反向超過門檻）或在開始移動之後又靜止超過 0.5 秒。死亡或過關時結算成 0／1。 |

兩者都遵守既有規則：硬邦邦、可計算、不含糊，樣本不足時回傳 `null`。

## 關卡層：第 8～12 關

### 第 8 關「你每次都在同一個地方起跳」— `jumpLead`

一條平路加一個坑。`adapt()` 把坑的左緣移到「你上次起跳點的正前方」，讓你的慣性起跳正好踩空。改變起跳時機就過得去（鐵則 4）。

坑寬固定 3 格（滿力跳跨得過），位置 clamp 在安全區間內，避免極端側寫值產生無解地形。

命內另有物理突變：過了坑之後 `setTune` 把 `gravityDown` 調高，接下來的每一次落下都比你預期的快。

### 第 9 關「你自己看」— 全部指標

畫面右側即時顯示側寫面板：落點、跳躍高度、速度、重生延遲、路線、猶豫次數。你能看見它在算你，而看見這件事本身就會讓你失誤。新指標 `hesitation` 在這關首次露面。

陷阱沿用既有詞彙，不引入新東西——這關的壓力來自被注視，不是來自機關。

### 第 10 關「已停止分析」— `flipControls`

轉場時宣布 `ANALYSIS SUSPENDED`。這關的 `adapt()` 真的什麼都不做，宣告是真的。

但它改用最粗暴的手段：門前那段路左右反轉。它沒在學你了，所以明著整你。玩家的疑神疑鬼加上反轉，是雙重打擊。

### 第 11 關「你死太多次了」— `deathCount`

`adapt(tiles, profile, { deaths })` 依本關死亡數逐步拆掉陷阱、把坑收窄。死越多關卡越簡單，但通關畫面記下這個數字。難度是你的自尊。

### 第 12 關「你這個人」— `swapDoor` + 分析報告

地形由整場側寫生成。場上數扇一模一樣的門，`swapDoor` 在你碰到真門的瞬間把它換成假的。

通關後顯示完整分析報告（`buildReport(profile)`），一行一個指標。

**報告的鐵律**：只能是可重現的事實陳述。措辭可以帶刺，但不得捏造統計——沒有母體資料就不准出現百分位。

## 測試策略

沿用現有策略，並新增：

- `traps.test.js`：`flipControls` 的狀態與重生歸零、`setTune` 的欄位合併、`swapDoor` 的位置互換與「碰到即死」的順序。
- `player.test.js`：`tune` 覆寫確實改變跳躍高度與落下速度；預設參數行為不變。
- `profile.test.js`：`jumpLead` 的掃描邊界（前方無障礙時不取樣）、`hesitation` 的結算時機。
- `levels.test.js`：第 8～12 關的 `adapt()` 在**任意側寫輸入**下都必須產生可通關地形（鐵則 4 的實作保證）。
- `playable.test.js`：笨機器人升級為讀得到 `world.flipped` 並自行反向；12 關全部必須有一條笨方法走得完。

## 實作過程中對本文件的修正

三處在寫程式時被測試推翻，記錄原因：

**第 12 關的地形改用速度，不用落點。** 原本打算把洞開在「你整場最常落腳的地方」。實作後笨機器人永遠過不去——洞追著落點跑，你落在哪它就搬到哪，變成追不完的迴圈。那是第 2 關的梗，在最後一關會退化成刁難。改用 `median(speeds)`：速度描述你這個人，而且不會因為洞搬家就改變，沒有回饋迴圈。

**第 11 關與第 9 關都不用橫掃的刺。** 兩關原本都排了 `sweepSpike`，實測都讓玩家在門口跟刺搶時間——刺從右邊逼近，而門前又剛好要跳一個洞、再跳上移走的門。那正是鐵則 7 明文禁止的「跟時間賽跑」。兩關都換成 `dropBlock`：它砸在你站的那一格，往前走就躲得掉，不吃時機只吃注意力。

**`setTune` 必須容忍沒有 `tune` 的世界。** 關卡驗證測試會拿一個最小化的假世界去套用所有動作，`Object.assign(undefined, …)` 會直接炸掉。改成回退到 `DEFAULT_TUNE`。

另外，笨機器人測試的極端側寫產生器補上了 `jumpLeads` 與 `hesitations`——不補的話第 8 關的 `adapt()` 會在 `median(undefined)` 崩潰，而那正是這條測試存在的理由。

## 對設計文件的修正

原設計文件（`2026-07-23-troll-platformer-design.md`）第 10 關寫的是「它宣布已停止分析，然後真的不再適應。純靠操作」。本文件把「純靠操作」改成「改用左右反轉」——原版沒有給那一關任何實際手段，會變成一關無梗的平路，違反鐵則 6（每關至少三個梗）。

其餘各關與原設計文件一致。
