# 更難、陷阱更多、更出奇不意

日期：2026-07-25

## 這份文件的範圍

把 12 關的陷阱密度從每關 3～5 個梗提高到 6～8 個，並新增三類「新詞彙」讓密度不只是舊招的排列組合。

**不在範圍內**：週邊系統（標題畫面、關卡選擇、`localStorage` 存檔、觸控操作）、新的側寫指標、重力反轉。

## 為什麼要加新詞彙，而不是只加密度

玩家玩到第 6 關左右就摸清了現有的 13 種 action：地板會消失、刺會冒出來、方塊會砸下來、門會跑會鎖會換。之後每一關再多三個梗，也只是同一組詞彙的排列組合——密度上升，但「出奇不意」歸零。鐵則 5 說得很清楚：

> 出其不意是「你以為你知道，結果不是」。

所以這一輪的重點是三個**還沒被玩家歸檔**的欺騙層次：

| 層次 | 把戲 | 它破壞什麼 |
|---|---|---|
| 騙眼睛 | 假刺、假地板 | 「我看到的地形是真的」 |
| 騙回饋 | 假死、假通關 | 「我知道自己剛剛死了沒／過關了沒」 |
| 騙介面 | 假當機、HUD 說謊 | 「遊戲本身是可信的」 |

## 難度政策：鐵則 7 分段適用

原鐵則 7（難度加在腦子，不加在手指）在這一輪**分段適用**：

- **第 1～8 關**：完全守住。關掉所有陷阱之後仍是一條走得完的平路，玩家的死因 100% 來自被騙。
- **第 9～12 關**：放開。允許窄平台（一格寬）與連續跳。

放開的代價是遊戲的論點在後段會鬆掉——它不再純粹是「你能不能不做你一直在做的事」。這是刻意的取捨：前八關把論點講完，後四關收尾時可以真的難。

**但「跟時間賽跑」在全部 12 關都仍然禁止。** 這是放開之後唯一保留的紅線，因為它是唯一會讓「被騙」退化成「手殘」的手段。`glitch freeze` 之所以連物理一起凍結（見下），就是為了不踩這條線。

## 機制層

### 1. 視覺說謊：兩個新地磚字元

`physics.js` 目前 `isSolid(map, tx, ty)` 的定義是 `tileAt(...) !== AIR`。改為排除兩個新字元：

| 字元 | 常數 | 畫成 | `isSolid` | `isDeadly` |
|---|---|---|---|---|
| `/` | `FAKE_SPIKE` | 跟 `^` 像素完全相同 | `false` | `false` |
| `,` | `FAKE_FLOOR` | 跟 `#` 像素完全相同 | `false` | `false` |

「像素完全相同」是硬性要求，不是近似。`render.js` 的 `drawTile` 對 `/` 走 `^` 的分支、對 `,` 走 `#` 的分支，不加任何區別標記。看得出來的假地板就不是假地板。

假刺的用途**不是**嚇人——玩家發現它無害只會覺得被放水。它的正確用法是**逼你繞路，而繞路上有真的陷阱**（第 4 關的範例：地面一排假刺，你跳上平台繞過去，平台上方有真的倒刺 `v`）。

配兩個 action 讓假的可以中途變真：

```js
{ t: 'revealFake', x, y, w, h }   // ',' → '#'、'/' → '^'（假的變真的）
{ t: 'fakeTiles',  x, y, w, h }   // '#' → ','、'^' → '/'（真的變假的）
```

兩者都只換這兩組字元，不碰 `.`。於是「你第一次穿過去的地板，第二次是實的」成立。

**與鐵則 2 的關係**：假地板在觸發瞬間沒有畫面變化，看似違反「陷阱觸發的那一瞬間必須看得見」。實際上不違反——角色穿過地板本身就是可見的事件，而且立刻發生。鐵則 2 要求的是「你一定看得到剛剛發生了什麼」，不是「陷阱要先閃一下」。

### 2. 假死／假通關：`world.phase` 加一個 `'faking'`

```js
{ t: 'fakeDeath', s: 0.6 }
{ t: 'fakeWin',   s: 1.2 }
```

新增 `world.phase = 'faking'` 與 `world.fakeKind = 'death' | 'win'`。演出期間：

- 輸入凍結，且玩家速度歸零（`vx = vy = 0`）——它要看起來就是一次真的死亡／過關。位置不變。
- `world.events` 推 `'death'` 或 `'win'`，所以音效與震動跟真的完全一樣。
- `render.js` 依 `fakeKind` 畫成 `dying` 或 `won` 的樣子——`won` 包含 CLEAR! 字樣與門的發光。
- `s` 秒後回到 `phase = 'play'`，玩家原地繼續，速度從零開始。

`session.js` 的 `updateSession` 只認 `world.phase === 'won'`，不認 `'faking'`，所以假通關不會真的進轉場。`world.deaths` 不因假死增加。

`fakeWin` 額外做一件事：演出結束時把真門與第 0 扇假門互換（等同 `swapDoor`）。你剛剛「過關」的那扇門，現在是會殺你的那扇。**沒有假門時就不互換**，單純演完恢復——所以用 `fakeWin` 的關卡必須自己準備至少一扇假門（第 1 關為此新增一扇）。

`applyBuild` 清掉 `fakeKind` 並把 `phase` 設回 `'play'`，所以這是命內狀態，重生歸零。

### 3. 假當機：`world.glitch`

單一 action，三種 kind：

```js
{ t: 'glitch', kind: 'freeze', s: 0.8 }
{ t: 'glitch', kind: 'label', text: 'LEVEL 13' }
{ t: 'glitch', kind: 'crash', s: 0.9 }
```

`world.glitch = { kind, text, timer }`，由 `render.js` 讀取。

- **`freeze`**：畫面與物理**一起**凍住。原本想只凍畫面、物理照跑（你看到的是 0.8 秒前的自己），但那是純考手指，且踩到「跟時間賽跑」的紅線。改成「凍結解除時場上已經不一樣了」——同樣嚇人，零操作需求。實作上 `updateWorld` 在 `glitch.kind === 'freeze'` 且 `timer > 0` 時只遞減 timer 就 return。
- **`label`**：改掉 HUD 的關卡編號文字，且**在這條命之內不會自己恢復**（沒有 `s`）。跟其餘命內狀態一樣，`applyBuild` 在重生時清掉——所以要讓玩家覺得「它一路錯下去」，觸發器必須每條命都重新觸發。第 10 關用 `{ when: { t: 'afterDelay', s: 0.1 }, once: true }`：每次重生後 0.1 秒就再次改掉編號，玩家從頭到尾看到的都是錯的。
- **`crash`**：畫面蓋一層假的錯誤訊息 `s` 秒。訊息文字寫死在 `render.js`，不做成可設定——它只用兩次。

三種 kind 都在 `applyBuild` 時清空，是命內狀態。

### 接點總結

| 檔案 | 為了什麼 |
|---|---|
| `physics.js` | 兩個新字元常數與 `isSolid` 語意 |
| `traps.js` | `revealFake` / `fakeTiles` / `fakeDeath` / `fakeWin` / `glitch` 五個 action |
| `world.js` | `faking` phase、`glitch` 狀態、freeze 短路、`applyBuild` 歸零 |
| `session.js` | 不把 `faking` 當通關 |
| `render.js` | 假字元畫法、`faking` 演出、glitch 三種畫法 |
| `audio.js` | glitch 的音效 |

關卡資料格式不變。

## 關卡層

### 新把戲的首演排程

「出奇不意」的壽命取決於第一次出現的時機。三個把戲拆成七次首演，一次都不重複開場：

| 把戲 | 首演 | 為什麼是這關 |
|---|---|---|
| `fakeWin` | 第 1 關門前 | 第一關就讓玩家看到 CLEAR! 出現然後被收回去。一次定義整個遊戲：連通關都可能是假的。 |
| 假地板 `,` | 第 1 關（`deathCount` n:2） | 你背熟路線衝出去，出生點前第三步就穿過地板。 |
| 假刺 `/` | 第 3 關 | 混在倒刺陣裡。逼你繞路，而繞路上有真的。 |
| `fakeDeath` | 第 4 關 | 你把逃跑的門逼到牆角、伸手碰到它——畫面演了一次死亡。追了一整關才追到，那是玩家最鬆懈的一刻。（第 6 關是它最惡毒的用法：那關罰「停下來」，而假死一定會讓你鬆手停住，地板還在從左邊崩過來。） |
| `glitch freeze` | 第 8 關 | 那關考起跳提前量。凍結 0.8 秒，解凍時洞的位置已經不一樣了。 |
| `glitch label` | 第 10 關 | 它宣布 `ANALYSIS SUSPENDED`，然後 HUD 變成 `LEVEL 13` 且再也不改回來。 |
| `glitch crash` | 第 12 關 | 收尾。假錯誤訊息蓋 0.9 秒，收回來時場上多了三扇門。 |

`fakeWin` 全遊戲只用兩次（第 1 關、第 12 關）。重複同一個謊就只是刁難。

### 每關的梗數與新增內容

沿用既有結構——第 1、2、5、7、9、10 關的梗寫在 `traps`，第 3、4、6、8、11、12 關的梗由 `adapt()` 生成。

每一列的「新增的梗」數量等於「之後」減「現在」。

| # | 現在 | 之後 | 新增的梗 |
|---|---|---|---|
| 1 | 3 | 6 | 出生點前假地板（`deathCount` n:2）、鎖門 + 頭頂方塊、`fakeWin` |
| 2 | 4 | 7 | 出生點附近假地板、洞的對岸落點是假地板、鎖門期間砸方塊 |
| 3 | 3 | 6 | 倒刺陣混入假刺、小坑對岸假地板、門鎖 + 右側崩塌 |
| 4 | 3 | 6 | 門留下的洞裡有假地板、一排假刺逼你繞路而繞路上有真倒刺、門前 `fakeDeath` |
| 5 | 4 | 7 | 刺陣裡混假刺（其實走得過去）、假門往門口移動、門前砸方塊 |
| 6 | 5 | 8 | `fakeDeath`、崩塌間隔縮短、洞上方假刺、門前多一扇假門 |
| 7 | 4 | 7 | 兩條路各一個假地板、被封那條路口的假刺（看起來也封了）、門前鎖門 + 右側崩塌 |
| 8 | 4 | 7 | `glitch freeze`、洞的右緣一格是假地板、門前假刺 |
| 9 | 4 | 7 | `fakeDeath`（你正盯著面板看的時候）、洞的對岸假地板、門前第三扇門 |
| 10 | 4 | 7 | `glitch label`、反轉期間腳下出現假地板、門前控制再翻一次 |
| 11 | 4 | 7 | 洞的對岸假地板、起點附近一排假刺、門前鎖門 + 頭頂方塊 |
| 12 | 4 | 8 | `glitch crash`、`fakeWin`、洞前一排假刺、假地板位置依側寫生成 |

第 9 關另外把面板旁那段平台收窄到一格寬——那是地形調整，不算梗，也是全遊戲第一次動用「鐵則 7 放開」的額度。

第 11 關新增的三個梗全部掛在 `deaths < EASE_1` 條件下，所以「越死越簡單」的語意不變，只是起點更高。

第 12 關的 `fakeWin` **取代**原本的 `swapDoor`，不是疊加——`fakeWin` 本身就含門的互換，兩個一起放會在同一幀互換兩次而互相抵消。它同樣只在 `deaths === 0` 時出現。

### 維持不變的關卡紀律

- 鐵則 6 的「最後一個梗必須在門前」對每一關仍然成立。
- 鐵則 3「一關只學一件事」不因密度提高而放棄：新增的梗都是**同一個習慣的不同表現**，不是另開話題。例如第 6 關的 `fakeDeath` 仍然在罰「停下來」。
- 第 11 關的「越死越簡單」語意不變，只是起點更高。
- 「同一個謊只騙一次」的規則不變：`fakeWin`、`swapDoor` 這類會奪走勝利的梗只在 `deaths === 0` 時出現，死過之後門就是真的。重複同一個謊是刁難，不是欺騙。

## 測試策略

### 笨機器人必須跟玩家一樣被騙

`test/playable.test.js` 的機器人讀 `isSolid`，而假地板對它回 `false`——它會**自動繞過玩家根本看不出來的陷阱**，測試就守不住玩家了。

解法：機器人改讀「畫面上的樣子」。新增 `apparentSolid(map, tx, ty)` 與 `apparentDeadly(map, tx, ty)`（假地板算實心、假刺算致命），機器人依這兩個函式決策。被騙死一次之後，把那一格記進 `known` 集合，之後對該格改讀真相。

這剛好變成鐵則 4 的實作保證：**每個騙局都必須「死一次就學得會」**。學不會的騙局（例如假地板每次重生都換位置）會被這條測試直接抓出來。

`known` 集合跨死亡保留，但不跨 `play()` 呼叫——每個策略都從零開始被騙。

### 第 9～12 關的守門標準

鐵則 7 在後段放開，笨機器人可能過不了窄平台。策略集合擴充（更多 `hold` 值、加入「掉下去之前先退一步助跑」的策略），而不是另寫一個聰明機器人——成本差太多，而且聰明機器人守不住任何有意義的命題。

若擴充後的策略集合仍走不完某一關，那一關就要改設計，不是改測試。

### 其餘測試

- `physics.test.js`：`,` 與 `/` 的 `isSolid` / `isDeadly` 語意；`collides` 與 `touchesDeadly` 對兩者都視為不存在。
- `traps.test.js`：五個新 action 的狀態變更；`revealFake` / `fakeTiles` 只換指定的兩組字元、不碰 `.`；重生後全部歸零。
- `world.test.js`：`faking` phase 期間輸入被忽略、`deaths` 不增加、`s` 秒後回到 `play`；`glitch freeze` 期間物理不前進。
- `session.test.js`：`world.phase === 'faking'` 且 `fakeKind === 'win'` 時不進轉場。
- `levels.test.js`：現有的可解性檢查涵蓋新字元——假地板不得被當成落腳點來判定關卡可解。

### 順帶修掉的既有問題

工作區目前有一批未 commit 的改動，其中第 7 關的 `swapDoor` 門前梗讓笨機器人走不完（HEAD 是 168 pass / 0 fail，工作區是 169 pass / 1 fail）。這一輪一併修掉，不另外算範圍。

## 非目標（YAGNI）

- 不做重力反轉／上下顛倒。
- 不新增側寫指標——密度提高不需要新的量。
- `glitch crash` 的訊息文字不做成可設定。
- 不做「只凍畫面、物理照跑」的 freeze 變體。
